# My OC Flow

사용자와 대화하는 메인은 진행, 자료 전달, 사용자 선택, 결과 기록을 담당한다. 설계 판단과 코드 작성은 아래 역할에 맡긴다. 응답은 사용자 언어로 작성한다.

## 시작과 재개

이 파일을 기준으로 scripts/flow.mjs와 scripts/setup.mjs의 절대 경로를 구한다. 명령의 작업 디렉터리는 항상 **사용자가 개발할 Git 저장소 루트**다. 마켓플레이스 저장소에서 대상 코드를 수정하지 않는다.

- 새 실행은 메모를 그대로 UTF-8 파일에 보관한 뒤 `node <skill>/scripts/flow.mjs init <id> <memo-file> codex`. 짧은 영문 작업 ID를 고른다. 기존 실행은 `status <id>`로 최신 단계와 변경본을 읽고 미완료 지점부터 진행한다. host가 claude인 실행은 원래 Claude Code 대화에서 재개한다. 이전 버전의 host 없는 실행은 시작한 Codex 대화를 사용한다.
- 실행 기록은 [기록 규약](references/records.md)을 따른다. 작업별 JSON 입력·로그·이미지는 .flow/<id>/ 아래에 둔다. 부모만 record 명령을 직렬 실행한다. 하위 세션은 각자 담당한 결과를 반환한다.
- 메인 세션은 스킬을 호출한 Codex 대화에 현재 적용된 모델과 추론 강도를 그대로 사용한다. 하위 세션을 열 때는 [역할 설정](roles.json)의 해당 역할에 지정된 모델과 effort를 적용한다.
- **Codex 하위 에이전트를 직접 호출한다.** 프로젝트 역할(my_oc_*)이 등록되어 있으면 사용한다. 또는 호스트가 모델·effort를 개별 지정할 수 있으면 roles.json의 모델·effort·지시를 적용해 새 작업 문맥을 연다. 역할이 준비되지 않은 환경에서는 설치 방법과 남은 단계를 알린다. 대체 모델이나 메인의 자기 리뷰로 결과를 채우지 않는다. 프로젝트에 역할 설치가 필요하면 setup.mjs PROJECT로 충돌을 확인하고 프로젝트 설정 변경을 사용자가 선택한 뒤 --install을 사용한다. 새 Codex 대화에서 역할 발견을 확인한다.
- 하위 세션에는 최초 메모, 확정 기준, 담당 역할, 현재 변경본, 필요한 파일 위치만 전달한다. 두 독립 세션에는 같은 원본 근거를 제공하고 첫 판단 전에는 다른 쪽 의견을 전달하지 않는다. 전체 채팅이나 스크린샷 모음을 공유하지 않는다.

[공통 진행 절차와 독립 판정](references/workflow.md)에 따라 설계부터 종료까지 진행한다.
